🏠 What is GateFlow?

GateFlow is a residential Visitor Management System. It replaces a paper visitor register with digital records while keeping the gate process simple for security staff.

The main idea is: identify → verify → contact if needed → record entry → record exit.
Every check-in is saved with a timestamp, so at any time the app knows exactly who is currently inside the society, who has already left, and when each event happened. This data is what powers the Dashboard counters and Reports page.

👥 Who can use it?

S
Security / Watchman
Handles gate verification, unexpected visitors and deliveries.
R
Resident
Creates guest invitations and receives arrival notifications.
A
Administrator
Manages resident records, system information and reports.

🔐 Login & roles

When the website opens, it first asks for a language. After that, the user must sign in and choose whether they are a Watchman/Security, Resident, or Administrator. Different roles are the foundation for a real multi-user system.

Watchman
Gate operations, QR scanning, flat search, visitors, deliveries and exits.
Resident
Guest invitations, temporary QR codes and arrival notifications.
Administrator
Resident management, reports and system oversight.

📷 QR scanning

A resident or guest can present a QR code. The security user opens Scan / Verify (also available from the 📷 button that floats on every screen), starts the camera, and points the phone camera at the QR. The QR value is read by the browser. The system then checks the value against the appropriate record.

Open scanner→Allow camera→Scan QR→Validate→Record entry
Each QR code encodes a unique token. A permanent resident's token matches their Resident ID; a guest's token is randomly generated when a resident creates an invite. When scanned, the app searches both lists for a match — if none is found, the visit is marked unrecognized and logged for the guard to handle manually.

🪪 Permanent residents

A permanent resident has a Resident ID and QR record already stored in the system. They do not need to register themselves again at every visit.

If the resident forgets the physical ID, the security user can use flat search for manual verification.

👶 Children

A child does not have to depend on carrying a smartphone. The project supports a physical ID workflow. The guard can verify the ID and record entry.

👵 Senior citizens

A senior citizen is not forced to use the app. A visitor can provide the flat number. Security searches the flat, sees the resident/contact information, calls the resident and registers the visitor after confirmation.

👨‍👩‍👧 Families / couples

A flat can contain multiple residents. The purpose is not to show unrelated people; it is to allow the security user to see who is associated with that flat when manual verification is required. The administrator can maintain the correct residents for each flat.

🔔 Resident Guest-Arrival Notification

When a guest invitation is scanned and verified at the gate, GateFlow creates a notification for the resident of that flat. The resident can open Notifications or tap the 🔔 bell to see: guest name, flat number, arrival time and confirmation that the guest was verified.

Resident creates invite→Guest QR scanned→Guest verified→Resident notified 🔔

💌 Expected relative

Resident enters guest name, flat, date and time. The system creates a temporary QR. The guest shows it at the gate. After validation, the resident gets a guest-arrival notification.

❓ Unexpected visitor

The visitor gives a flat number. Security searches the flat, sees the relevant resident/contact, calls the resident and records the visitor only after confirmation.

📦 Delivery

The delivery person does not need an account. Security enters basic details, stores entry time, and later presses EXIT to store the exit time.

📋 Queue

If several visitors arrive together, they can wait in a queue. Visitors are processed in arrival order. This demonstrates the Queue data structure from the project.

↶ Stack

The latest system operations are kept at the top of the Activity Stack. The demo includes an Undo latest action to make the Stack concept easy to demonstrate.

🌐 Language preference

The first screen asks the user to select English, Hindi or Marathi. The selected preference is remembered in the browser. You can change it anytime using the 🌐 button in the top bar or the floating 🌐 button on the screen.

The choice is stored in the browser's local storage, so it is remembered the next time this file is opened on the same device. A production version would fully translate every screen; this prototype focuses on demonstrating where that language layer plugs in.

🛠️ Technology used in this prototype

Frontend: HTML + CSS + JavaScript · QR camera: browser camera API through the QR scanner library · Demo database: browser localStorage.

Planned full-stack version: Python + MySQL, matching the software requirements in the capstone document.

📚 Project background

The capstone is based on the documented problem of slow paper registers and the research concepts of QR-based authentication, digital visitor registration, notifications, residential access control and tracking. Its contribution focuses on making those ideas practical for users with different levels of technological comfort.

Future work: RFID resident access, automatic gate integration, CCTV integration, facial recognition, SMS/push notifications, cloud deployment, emergency alerts and visitor analytics.
